# 投资人数据库增量同步与发布手册

版本：1.0（2026-11-18）
适用：自有服务器 crontab，MiraclePlus 投资人 API 增量 → 本地快照 → 发布门禁 → 上线或自动回滚。

## 1. 结论

一条 cron 命令完成一次增量维护：

```bash
python3 scripts/cron_investor_sync.py --mode update
```

内部顺序：

```
API updated_at 增量
  → 合并 CSV（先备份）
  → 重建 release
  → 113 条回归评测
  → 回归门禁
  → 切换 releases/current.json
```

发布失败时自动把 CSV 恢复到同步前的备份，指针不变，上一版继续服务。

## 2. 目录与数据边界

代码仓库只放脚本、测试和文档；真实数据放在服务器数据目录，仓库内用 `.gitignore` 排除。

```
/srv/investor-db/                 # 仓库根目录
├── scripts/                      # 代码
├── doc/                          # 标签表、场景词、验收集、发布策略
├── output/                       # 本地快照 CSV（不入库）
│   ├── investors_enriched_20260728_1745.csv
│   └── organizations_enriched_20260728_1745.csv
├── releases/                     # 发布产物、current.json、history.jsonl（不入库）
├── research/                     # 批次、状态、运行日志（不入库）
└── data/backups/                 # 同步前备份（不入库）
```

用 `--investors`、`--organizations` 可以指向仓库外的数据目录：

```bash
python3 scripts/cron_investor_sync.py \
  --investors /srv/investor-data/investors.csv \
  --organizations /srv/investor-data/organizations.csv \
  --state /srv/investor-data/sync_state.json \
  --report-dir /srv/investor-data/reports \
  --release-root /srv/investor-data/releases
```

## 3. 环境变量

只在服务器环境或 `EnvironmentFile` 中配置，不写进仓库：

| 变量 | 必填 | 说明 |
|---|---|---|
| `INVESTOR_API_CLIENT_ID` | 是 | OAuth client id |
| `INVESTOR_API_CLIENT_SECRET` | 是 | OAuth client secret |
| `INVESTOR_API_BASE_URL` | 否 | 默认 `https://api.miracleplus.com/build`，必须 HTTPS |
| `INVESTOR_API_SCOPE` | 否 | 默认 `public funds` |
| `INVESTOR_API_TIMEOUT_SECONDS` | 否 | 默认 20 |

示例见 `deploy/investor-sync.env.example`。

## 4. 首次运行

快照的 `last_updated` 是 2026-07-28。首次同步不传 `--since` 时会自动从快照最大时间减 1 秒开始，因此能接上快照之后的所有增量。

先干跑，只读不写：

```bash
python3 scripts/sync_investors_api.py --dry-run --max-pages 40
```

确认 `changed_total`、`conflicts`、`skipped_new` 符合预期后，再真实执行：

```bash
# 第一次建议只补空值，避免覆盖已有调研结论
python3 scripts/cron_investor_sync.py --mode fill

# 稳定后改成覆盖更新
python3 scripts/cron_investor_sync.py --mode update
```

`--mode fill` 只填空单元格；`--mode update` 还会覆盖非空但不同的值。

## 5. crontab

```cron
# 每天 03:17 跑一次；flock 防止重叠
17 3 * * * cd /srv/investor-db && . /etc/investor-sync.env && /usr/bin/flock -n /tmp/investor-db-cron.lock /usr/bin/python3 scripts/cron_investor_sync.py --mode update >> /var/log/investor-db/sync.log 2>&1
```

建议同时配置 logrotate，见 `deploy/logrotate.example`。

脚本内部还有一层 `research/.cron_sync.lock`，锁超过 6 小时视为陈旧锁并自动清理。外部 `flock` 和内部锁同时存在，任一层都能防止重叠。

## 6. 合并策略

| 情况 | 默认行为 |
|---|---|
| API `updated_at` ≤ 本地 `last_updated` | 跳过，不重复处理 |
| 本地空、API 非空 | 填入 |
| 本地非空、API 不同 | `fill` 保留本地并记 conflict；`update` 覆盖 |
| API 为空 | 永远不清空本地值 |
| 姓名、机构名、`org_id` | 只报告冲突，不改写 |
| 投资人所属机构 | 不改写；API 的 fund 关联与本地快照存在差异 |
| 本地不存在的投资人/机构 | 默认跳过并计数；`--include-new` 才新增 |
| 只有 `last_updated` 变化 | 写入时间戳，但不触发发布 |
| 机构匹配 | 先查 API fund id 映射，再按中文名/全名/英文名精确匹配 |

新增机构会按 `org_<sha256(chinese_name)[:8]>` 生成稳定 ID，与现有 `org_id` 规则一致。

## 7. 发布与回滚

`run_investor_release.py` 每次创建新目录 `releases/v<N>_<YYYYMMDD_HHMM>`，不覆盖旧版本。

门禁默认用当前生效版本的 `eval_report.json` 做回归基线；没有则用 `doc/investor_search_release_policy_v3.json` 里的 `baseline_report`。

失败路径：

| 阶段失败 | 动作 |
|---|---|
| 同步 API/IO 错误 | 不写 CSV，退出 30/28 |
| 构建失败 | CSV 保持同步后的状态？否——cron 会恢复备份 |
| 评测失败 | 恢复 CSV 备份，release 目录保留供排查 |
| 门禁不通过 | 恢复 CSV 备份，指针不变，退出 24 |

手动回滚到上一版：

```bash
python3 scripts/manage_release.py rollback
python3 scripts/manage_release.py status
```

## 8. 日志与监控

| 产物 | 路径 |
|---|---|
| 同步报告（含字段级 old/new） | `research/api_sync/<run_id>_report.json` |
| cron 运行日志 | `research/runs/cron_<timestamp>.json` |
| 发布日志 | `research/runs/release_<timestamp>.json` |
| 发布历史 | `releases/history.jsonl` |
| CSV 备份 | `data/backups/<run_id>/` + `manifest.json` |

建议告警：

- 退出码非 0（24 门禁、30 API、28 IO、40 锁占用）。
- `research/runs/` 最新 cron 日志 `status` 不是 `ok`/`noop`。
- 同步报告 `conflicts` 突然放大（说明 API 与本地口径出现系统性差异）。
- `skipped_new` 长期很高且 `changed_total` 长期为 0（说明本地存量已停止更新，需要评估是否纳入新增）。

## 9. 退出码

| 码 | 含义 |
|---:|---|
| 0 | 成功或无变化 |
| 2 | 参数错误 |
| 24 | 回归门禁不通过 |
| 25 | 评测/数据失败 |
| 26 | manifest 完整性失败 |
| 28 | IO 失败 |
| 30 | API 失败 |
| 31 | 数据/状态文件失败 |
| 40 | 锁被占用 |

## 10. 已知边界

- 不自动改投资人所属机构。API 的 `fund` 关联与本地快照存在系统性差异（同一投资人 ID 在两边对应不同机构），改机构会破坏历史标签，必须人工确认。
- 默认不新增投资人。API 全量 1.8 万人，本地是 3,300 人 curated 集合；直接全量导入会改变召回分布。
- 增量只按 `updated_at` 判断。若上游批量回填旧数据但不更新 `updated_at`，本次同步不会发现。
- 身份字段（姓名、机构名）冲突只记录不覆盖。姓名差异可能是翻译、别名或上游修正，交给人工判断。
